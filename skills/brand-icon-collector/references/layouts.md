# 版式规范

所有版式的共同前提：**浅色底配深色文字**。图标本身多为彩色或黑色，深底会吃掉黑色图标。底色用 `#FFFFFF` 或 `#F4F5F7`。

## 一、分类一览图（PNG）

PNG 尺寸由内容推出，不要写死。参数：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| 列数 | 4 | 12 项正好 3 行；项数不是 4 的倍数时最后一行左对齐，允许留白 |
| 单元格宽 | 282 | 4 列 + 左右各 34 边距 ≈ 1196 宽 |
| 单元格高 | 214 | 图标 116 高 + 名称 + 英文名，行间不挤 |
| 图标边长 | 116 | 相对单元格宽约 41%，视觉饱满 |
| 页边距 | 34 | |
| 标题区高 | 104 | 标题 26px 粗体在 y=34，副标题 12px 灰在 y=70 |

纵向锚点（相对单元格顶）：图标 y+30，中文名 y+158，英文名 y+184。底部留 62 说明行。

绘制要点：

```python
# 图标居中
img.paste(ic, (int(x0 + (cell_w - icon) // 2), y0 + 30), ic)   # 坐标必须 int
# 文本居中
tw = d.textlength(name, font=f_name)
d.text((x0 + (cell_w - tw) / 2, y0 + 158), name, font=f_name, fill="#1F2329")
```

同一格放多个条目时（例如某厂商有两个生图模型），按前一个文本实际宽度推进：

```python
cx = x + 16
for b in items:
    ...
    cx += 58 + d.textlength(name, font=f_name) + 20
```

固定步长会在长名字上翻车——实测「即梦 Dreamina」会压到后面的图标上。

**另一个隐性坑：单元格内容溢出列边界。** 即便步长算对了，一格内两个条目的总宽（约 380px）也可能超过预设列宽（324px），最后一两个字母会越界到下一列的空隙里，被下一列先绘制的图块盖掉——表现为"最后一个字母凭空消失"。修法是列宽按最宽单元格动态算：

```python
need = 0
for _, items in multi:                      # 每个厂商的每个模态格
    for mk, *_ in mods:
        wsum = 16
        for b in items_of(mk):
            wsum += 58 + textlength(b["zh"]) + 20
        need = max(need, wsum)
CW = max(324, need + 8)
```

画布总宽随 CW 推导，不要写死。

字体：中文 `msyhbd.ttc`（微软雅黑粗）/ `msyh.ttc`（常规），拉丁 `arialbd.ttf` / `ariblk.ttf`。macOS 用 `PingFang.ttc`，Linux 用 `NotoSansCJK`。字体缺失时降级到 `ImageFont.load_default()`，不报错但会很难看，务必在核验截图里检查。

## 二、HTML 总览页

两版：**按分类**和**按厂商**。两版的卡片都用「彩色 / 单色」双格预览 + 四个下载按钮。

风格基线：

- 页面底 `#F4F5F7`，卡片白底 `#FFFFFF`、`1px solid #E6E8EB`、圆角 14px
- 最大宽 1180px 居中，卡片网格 `repeat(auto-fill, minmax(258px, 1fr))`，间距 16px
- 分区标题左侧 4px 蓝色竖条（`#2F5BD7`）+ 18px 粗体 + 灰色计数胶囊
- 预览格：`height: 92px`，浅底 `#F7F8FA`，内框 1px `#EEF0F3`，图标 46×46
- 下载按钮做成药丸小标签：11.5px，`#2F5BD7` 文字，`1px solid #DFE4EE` 边框，圆角 999px
- 无彩色版的那一格显示灰色「—」，不要留空也不要塞占位图

**数据必须从 `manifest.json` 生成**，标题里的品牌数、文件数、分区计数都用 `len()` 算出来。手写字符串在加品牌时必漏改——实测两轮之后标题还停在旧数量。

按厂商版的结构：每家厂商一张卡片，内部三栏（语言 / 生图 / 视频），空格标「—」。多模态厂商排前面（按模态数降序），单一模态厂商压成下方一排小胶囊。

公司标识（如 Anthropic 的公司标）不是模型，不参与模态矩阵，生成时要过滤掉，否则会出现「Anthropic 只有语言模态」这种误读。

## 三、厂商 × 模态矩阵（PNG）

表达"谁在做全模态"最有效的一页。结构：

- 表头行：`厂商 | 语言 | 生图 | 视频`，浅灰底 `#F7F8FA`
- 每行一个厂商，行高 118；左侧厂商名 17 粗体 + 「N 个模型」11px 灰
- 单元格内图标 48×48 + 中文名 + 英文名
- 空格显示浅灰「—」`#CDD2DA`
- 隔行浅底 `#FCFCFD` 辅助阅读
- 下半部分「仅覆盖单一模态的厂商」压成 6 列小格，图标 38px

列宽参考：厂商列 210，模态列各 324。

## 四、README 结构

固定四段：目录结构（带注释的树）→ 清单表（按分类分表，含「彩色版」列并注明缺失原因）→ 关于自绘标识的说明 → 来源与许可 + 使用建议。

清单表里「彩色版」列写 `✅` 或 `—（原因）`，原因要具体：「官方标准色即黑色」「暂缺官方彩色源」，不要只写 `—`。
